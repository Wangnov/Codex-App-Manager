# Mirror 讨论 #74：接管安装与状态显示选择了不同目标

调查日期：2026-10-01。讨论：https://github.com/Wangnov/codex-app-mirror/discussions/74

用户提供的 v0.5.10 日志包含 51 次接管调用，目标为注册的
`OpenAI.Codex_26.917.6896.0_x64__2p2nqsd0c76g0`。随后启动调用却使用
`C:\Users\Administrator\AppData\Local\Programs\Codex` 便携目录。
截图中接管按钮仍存在，启动另外报立即退出（exit=0）。

代码确认 `win_adopt` 使用 MSIX 优先的原始检测，而状态、规划和启动使用
优先保留既有便携记录的检测。同机残留 MSIX、且便携安装的版本已变化时，
接管操作更新的是另一个安装的记录，界面所选便携安装的旧版本记录仍不匹配。

接管改为复用状态与启动的检测逻辑。回归夹具同时创建默认目录安装与记录选择的
另一个便携安装，并让后者的版本发生变化；旧逻辑接管错误目标，修复后刷新界面
所选安装的记录。前端验证接管成功后“开始管理”消失，版本选择入口恢复。

此修复解决目标选择不一致。exit=0 仍需报告者在修复版本中确认；单凭退出码无法
确定是单实例转交还是启动失败。没有清理用户数据、修改官方二进制或设置全局 CLI 覆盖。
