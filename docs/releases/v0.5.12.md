> 修复 Windows 便携版的双击启动，并完善协议入口和任务栏快捷方式。
> Fix Windows portable launchers and their protocol and taskbar integration.

## 🐛 修复 · Fixes

- **直接双击启动**：便携安装目录中的 `Codex.exe`、`ChatGPT.exe` 和 `LaunchCodex.exe` 现在都通过原生入口启动，并带上正确的 CLI 路径和工作目录。
  All three entry points in the portable install folder now launch with the correct CLI path and working directory.
- **兼容旧便携安装**：更新或重新安装时，旧的平铺目录自动迁移到新布局；迁移失败会恢复原来的文件。
  Updates and reinstalls migrate older flat layouts automatically, restoring the previous files if migration fails.
- **协议链接入口**：Windows 默认应用中新增「Codex (Portable)」，选中后通过便携入口处理 `codex://` 链接；卸载时清理该注册。
  Select “Codex (Portable)” in Windows Default apps to open `codex://` links through the portable launcher. Uninstalling removes its registration.
- **任务栏与中文路径**：开始菜单快捷方式关联到便携入口；请从更新后的开始菜单项重新固定到任务栏。中文、空格和特殊字符路径也能正确保存，较长安装路径不会重复嵌入卸载命令。
  Start-menu shortcuts identify the portable launcher correctly; recreate taskbar pins from the updated Start-menu entry. Shell metadata preserves Unicode and special characters, and uninstall commands avoid duplicated encoding on long paths.

**验证范围：** 自动回归、真实 x64/ARM64 MSIX 提取和安装器检查已通过。协议唤起、任务栏重新打开与登录后的浏览器联动仍需受影响机器复测。
**Verification scope:** Automated regression, real x64/ARM64 MSIX extraction and installer checks passed. Protocol activation, reopening taskbar pins and signed-in browser actions still need confirmation on affected machines.

**Windows 签名状态:** 本版安装器没有 Authenticode 代码签名,首次运行可能出现 SmartScreen 提示。`.sig` / `latest.json` 的 Tauri updater 字节签名用于验证更新文件,不代表 Windows 发行者身份。SignPath Foundation 申请已不再推进,项目改为采用付费云 HSM 证书;证书配置完成前发布保持未签名。参见 [代码签名政策](https://github.com/Wangnov/Codex-App-Manager/blob/main/docs/code-signing-policy.md)与 [Windows signing and verification](https://github.com/Wangnov/Codex-App-Manager/blob/main/docs/windows-signing.md)。
**Windows signing status:** This release's installers are not Authenticode-signed, so SmartScreen may warn on first run. Tauri updater signatures in `.sig` / `latest.json` verify update files and do not establish Windows publisher identity. The SignPath Foundation application is no longer being pursued; the project is moving to a paid cloud-HSM certificate, and releases stay unsigned until one is configured. See the [code signing policy](https://github.com/Wangnov/Codex-App-Manager/blob/main/docs/code-signing-policy.md) and [Windows signing and verification](https://github.com/Wangnov/Codex-App-Manager/blob/main/docs/windows-signing.md).
